# 上线前自检与商用边界

审计日期：2026-09-01  
审计对象：AI Token Gateway 当前 `main` 工作区  
审计目标：核对管理员、前端用户、租户/项目、Token、渠道调度、计费、媒体接口、生产安全和部署材料是否达到受控商用上线条件。

## 1. 结论摘要

当前系统已经具备 AI 大模型中转站的核心商用闭环：平台管理员与租户用户 audience 隔离，租户和项目资源有服务层二次校验，API Token 绑定创建者、项目、分组和状态，渠道支持优先级/权重/失败切换，计费支持预占、实际 Usage 结算、幂等和待对账状态，后台高风险写操作支持实时 TOTP Step-up。

**上线结论：可投入受控商用，不建议在未完成生产验收前直接开放无限制公开注册或对外宣称覆盖所有厂商的全部高级 API。** 正式开放前必须完成生产密钥轮换、SMTP 验证、边缘 Captcha/WAF、真实 PostgreSQL 集成测试、渠道实测和备份恢复演练。

## 2. 已检查并已实现

| 领域 | 当前结果 | 影响范围 |
| --- | --- | --- |
| 平台角色 | 支持创建、编辑、停用自定义角色，选择系统权限并绑定已注册用户；仅 `platform_owner` 可变更 | 管理员垂直越权 |
| 根角色保护 | `platform_owner` 不可编辑/停用；最后一个有效管理员受保护；平台所有者账号不能被普通用户管理员修改 | 防止管理面板锁死 |
| Session | 密码、邮箱、关键角色/权限、账号状态变化会撤销相关旧 Session；解析时再次校验用户和租户状态 | 旧会话复用 |
| 用户创建 | 后台创建用户接口明确拒绝；客户用户只能前端自注册 | 用户生命周期边界 |
| 租户成员 | 租户所有者/管理员可管理成员；角色变更、暂停、移除会撤销创建者相关 Token | 水平越权与密钥失控 |
| 项目 | 项目创建、修改、软删除、项目成员授权和项目角色校验已实现 | 项目级资源隔离 |
| API Token | 只能由租户用户创建/撤销；列表按 `tenant_id + created_by` 返回；绑定项目、分组、模型、IP/CIDR、域名、过期和速率规则 | 客户密钥归属 |
| 渠道 | 上游 Key 加密保存，列表只显示脱敏预览；渠道支持新增、编辑、暂停、启用、软删除和模型发现 | 上游凭据安全 |
| 路由 | 分组是渠道集合和策略；同模型按优先级分层、同层权重选择；可重试上游错误自动切换，连续失败触发短时熔断 | 可用性与兜底 |
| 计费 | 预占余额、按上游 Usage 结算、释放差额、幂等键、渠道重绑定、`settlement_pending` 和人工补结算入口已实现 | 财务一致性 |
| 多计量 | 支持 Token、缓存、推理、图片/音频/视频 Token、图片数量、字符、秒数、请求、查询、会话、页数等组件；缺少可靠计量不会静默按零放行 | 多媒体计费 |
| 管理 MFA | 管理员全局 MFA 可在系统设置开关；开启前要求所有有效管理员已绑定 TOTP；高风险管理写操作要求 `X-MFA-Code` | 后台高风险操作 |
| 用户 MFA | 基于 `github.com/pquerna/otp` 的 TOTP 绑定、确认、登录校验和安全关闭 | 账户安全 |
| 注册邮件 | 生产公开注册可进入 `pending`，SMTP STARTTLS 发送一次性验证链接，支持验证和安全重发 | 防止未验证账号登录 |
| 部署 | Caddy HTTPS、PM2、systemd 恢复、回环监听、PostgreSQL 最小权限、备份/回滚流程已有文档和模板 | 生产运维 |
| 前端体验 | 修复 `#home` 首页路由、无权限页面、只读 Token 操作入口和移动端 Hero 横向溢出；认证/API 响应禁止缓存 | 页面可用性与敏感信息保护 |

## 3. 仍然存在的边界与影响

以下项目不是本轮遗漏，而是当前明确的产品边界；在对外合同、官网和客户文档中不能写成“已完整支持”。

| 项目 | 当前状态 | 上线影响和建议 |
| --- | --- | --- |
| 退款、套餐、自动充值、财务导出、完整账单对账 | 暂不实现 | 只能使用预付余额和人工入账/补结算；上线前明确财务流程和人工审批责任 |
| 主动渠道探针、告警通知、跨实例错误聚合 | 暂不实现 | 依赖人工查看运营面板；生产应由外部监控、日志平台和告警系统补足 |
| 高可用集群 | PM2 仅为单机进程守护 | 单机故障仍会中断服务；需要负载均衡、共享限流/队列、数据库 HA 后才能承诺高可用 |
| Captcha、Bot 防护、WAF | 应用内未内置 | 公开注册和 Relay 入口必须放在 CDN/WAF 边缘，应用节流不能替代 WAF |
| OpenAI/Gemini/Grok 高级能力 | 已覆盖主流文本、Embedding 和部分图片/音频/视频基础接口 | Responses 全量事件、异步高级能力、Files/Live/Realtime、厂商专有编辑等需逐项实测后再开放 |
| Anthropic 多媒体/Embedding | 当前只承诺 Messages 及图片内容块 | 不应伪装成官方不存在或当前未接入的能力 |
| 跨厂商 API 完全等价 | 不成立 | 模型是否支持能力、Usage 和价格以渠道实际返回及平台映射为准；为每个生产模型做协议/计费验收 |

## 4. 安全与配置发现

### 已通过的检查

- 未发现前端 `console.log` 或 `debugger` 临时代码；ESLint 配置也将 `debugger` 设为错误。
- `git ls-files` 未包含 `.env.local`；`.gitignore` 排除了 `.env`、`.env.*`，但保留 `.env.example`。
- `#home`、登录、注册、模型目录和未知 hash 路由均已通过浏览器检查；桌面和 390px 移动视口无横向溢出。
- 上游 URL 有协议、凭据、查询参数、私网/回环/元数据地址和连接时 DNS 复核限制，禁止自动重定向。
- JSON 管理请求拒绝未知字段并限制请求体大小；媒体上传限制文件和 JSON 大小。
- Cookie 管理接口执行来源检查，CORS 只接受显式来源；响应包含 CSP、HSTS（由 Caddy）、防 MIME 嗅探和禁止 iframe 等安全头。
- 管理接口按 audience、平台权限、租户路径和服务层资源归属重复校验；前端隐藏菜单不是安全边界。
- 审计日志不保存请求体、Authorization、API Key、密码或上游响应，并对 IP/User-Agent 做哈希。

### 上线前必须处理

1. 本机 `.env.local` 当前含开发数据库密码、Token Pepper、Session Pepper 和 MFA 加密密钥。它虽然未被 Git 跟踪，但所有这些值必须在生产重新生成；发布包、备份、截图、日志和 shell history 都不得包含它。
2. 生产必须使用非超级用户 PostgreSQL 账号、`COOKIE_SECURE=true`、HTTPS、明确 `CORS_ALLOWED_ORIGINS`、回环 `HTTP_ADDR` 和明确 `TRUSTED_PROXY_CIDRS`。
3. 开启公开注册前，在“系统设置 → 功能开关”打开“开放用户注册”；如需邮箱验证，同时打开邮件总开关和“邮箱验证码”，并在“系统设置 → 邮件设置”配置 HTTPS 公开地址和可用的 SMTP STARTTLS；同时在边缘配置 Captcha/WAF。
4. 迁移必须执行到 `036_model_status_feature.sql`；正式包中的 `migrations/` 必须和二进制来自同一提交。
5. 生产应启用外部依赖漏洞扫描；本次使用官方 npm registry 检查生产依赖为 0 个已知漏洞，但仍不能替代发布镜像和运行环境扫描。

## 6. 发布门禁

只有以下条件全部满足，才建议把注册开关对外打开：

1. 生产环境变量和数据库连接已由专人核对，所有开发密钥已轮换。
2. 数据库迁移完成并有可恢复备份，恢复演练成功。
3. 所有有效平台管理员已绑定 TOTP，并验证角色变更会使旧后台 Session 失效。
4. SMTP 验证、重发、密码重置和账号状态流程在真实域名下通过。
5. Caddy、PM2、PostgreSQL、磁盘、证书和外部 WAF/监控均有负责人和告警渠道。
6. 客户文档只承诺当前真实可用的接口；厂商高级能力按模型和账号权限逐项开放。
7. 发布版本已提交到 Git，发布包不含 `.env*`、`node_modules`、本地缓存、日志、数据库转储和完整密钥，并完成 SHA-256 校验。

在这些条件满足前，推荐关闭公开注册，仅用 `bootstrap-admin` 建立平台所有者，再从受控测试账号验证租户和 Token 闭环。
